การออกแบบที่ดีจะมีความหมายก็ต่อเมื่อได้ส่งมอบออกไปจริง โมดูลสุดท้ายนี้จะเชื่อมทุกอย่างเข้าด้วยกัน อธิบาย API ด้วย spec พิสูจน์ด้วยการทดสอบว่าใช้งานได้จริง แล้วนำไปสร้างอย่างสะอาดด้วย TypeScript

## จากการออกแบบสู่เซอร์วิสที่ทำงานได้จริง

<Mermaid code={flowDiagram} title="spec การสร้างจริง และการทดสอบต่างเสริมกันและกัน" />

spec คือบานพับสำคัญ ทำหน้าที่บันทึก contract ไว้ให้คนที่มาใช้ API ใช้ generate code ฝั่ง client และเอกสารได้ แถมยังเป็นตัวอ้างอิงให้ test ของคุณเทียบว่าของจริงตรงกับที่ประกาศไว้หรือไม่

## โมดูลนี้ครอบคลุมอะไรบ้าง

- **OpenAPI** — อธิบาย API เป็น contract ที่เครื่องอ่านได้
- **Testing APIs** — การทดสอบแบบ unit, integration และ contract
- **Building with Hono** — การสร้างจริงด้วย TypeScript ที่ผสานเป็นหนึ่งเดียว
- **Best-practices recap** — เช็กลิสต์รวบทุกอย่างที่คุณได้เรียนรู้มา

<Callout title="spec คือ contract">
ไม่ว่าคุณจะเขียนเอกสาร OpenAPI ก่อน (spec-first) หรือ generate จาก code (code-first) ให้ถือว่า spec คือ single source of truth ว่า API รับปากอะไรไว้บ้าง ทั้งคนที่มาใช้ API เอกสาร mock server และ contract test ล้วนไหลออกมาจากจุดนี้ ถ้า spec คลาดเคลื่อนหรือไม่มีเลย การเชื่อมต่อจะพังเงียบ ๆ
</Callout>
